# 每日策略归档自动化方案（Plan01）

## 1. 日期

2026-08-03（Asia/Shanghai）

## 2. 目标

在每天策略讨论结束后，由 Codex 定时任务自动汇总本任务中尚未归档的新增策略，并按递增编号生成新的 Markdown 计划文档，使 Coding Multi-Agent 的设计决策持续沉淀、可追踪且不覆盖历史版本。

## 3. 背景

`Plan00.md` 已记录 Coding Multi-Agent 的动态角色、任务调度、工作区隔离、质量验证和 MVP 实施方案。后续讨论需要持续形成新的计划文档，因此增加每日自动归档机制，并将所有 Plan 文档集中到独立目录中管理。

## 4. 关键决策

- 所有计划文档统一存放在 `/Users/donbblu/codex/multiAgent/Plan`。
- 现有 `Plan00.md` 已移动为 `Plan/Plan00.md`。
- 后续文件使用 `PlanNN.md` 命名，取目录内现有最大编号加一。
- 编号至少使用两位十进制数字，例如 `Plan00.md`、`Plan01.md`、`Plan02.md`。
- 已有文件不得被覆盖；编号冲突时继续递增，直到找到未占用的文件名。
- 自动化每天 00:00 按 Asia/Shanghai 时区触发。
- 自动化绑定当前 Codex 任务，通过现有对话上下文识别新增策略。
- 当天没有尚未归档的新增策略时跳过，不创建空文档。
- 自动化只允许在 `Plan` 目录内新建 Plan 文档，不修改或删除已有 Plan 文件。

## 5. 自动化流程

```text
每天 00:00 触发 Codex 定时任务
        ↓
加载当前任务的对话上下文
        ↓
判断是否存在未归档的新增策略
   ├─ 否 → 跳过并报告
   └─ 是
        ↓
扫描 Plan/PlanNN.md
        ↓
计算 max(NN) + 1
        ↓
检查目标文件是否已存在
   ├─ 已存在 → 继续递增
   └─ 未存在
        ↓
整理策略并创建新 Markdown 文档
        ↓
返回新文档的绝对路径
```

## 6. 文档内容规范

每份自动生成的 Plan 至少包含：

- 日期
- 目标
- 背景
- 关键决策
- 架构或流程
- 执行步骤
- 约束与风险
- 待办事项

归档内容只基于本任务中实际讨论过的信息，不虚构尚未达成的决策，并与已有 Plan 保持连续性。

## 7. 执行步骤

1. 保持 `/Users/donbblu/codex/multiAgent/Plan` 作为唯一的 Plan 归档目录。
2. 每次运行前扫描该目录内严格匹配 `PlanNN.md` 的文件。
3. 读取现有 Plan，确认哪些策略已经归档。
4. 对照当前任务新增对话，判断是否产生新的策略、架构或流程决策。
5. 有新增内容时，选择下一个未占用编号并创建新文档。
6. 创建完成后报告绝对路径；无新增内容时明确记录本次跳过。

## 8. 约束与风险

- 本自动化仅能使用当前 Codex 任务的上下文，其他任务中的讨论不会自动进入本归档流程。
- “是否属于新增策略”由 Agent 根据对话语义和已有 Plan 判断，不是严格的数据库事件游标。
- 本地文件归档依赖电脑保持开机、Codex 桌面应用运行，以及目标目录在触发时可访问。
- 如果任务上下文被拆分到其他对话，需要手动迁移内容或为其他任务单独配置归档流程。
- 自动化首次配置时曾因状态值格式不符合应用校验而未保存；现已使用有效配置重新创建，自动化 ID 为 `plan`。
- 不得通过覆盖旧文件的方式修正历史记录；需要修订时应新建后续 Plan，并明确说明变更。
